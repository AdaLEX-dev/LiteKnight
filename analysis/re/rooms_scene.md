# Room, Scene, and Asset Lifecycle Reconstruction

**Scope:** `r1_1` reconstruction test room and the engine-level room lifecycle.
This is not a full procedural-generation reconstruction. The native
`r1_1_visual` scene is a controlled reverse-engineering test chamber assembled
from real `r1_1` data; it is not proven to be the game's canonical starting level
or character-select scene.

All serialized door transforms have identity rotation/scale. The world-space
barrier rectangles are `south [17.5,12.0]..[22.5,13.0]`,
`north [17.5,28.0]..[22.5,29.0]`, `west [11.5,18.0]..[12.5,23.0]`, and

`south [17.5,13.4]..[22.5,14.9]`, `north [17.5,26.1]..[22.5,27.6]`,
`west [12.9,18.0]..[14.4,23.0]`, and `east [25.6,18.0]..[27.1,23.0]`.

The 49 `skin_wall` objects are interior visual variants on layer 12 (`Obstacle`)
and have no colliders. The serialized `wall_group` contains no room-perimeter
colliders. Wall collision is runtime-generated by `RGRoomX.CreateWall`
(`0xDEBE3C`), which instantiates `MapManagerLevel.wall_list` prefabs
(`wall601`/`wall602`) around the perimeter and parents them to
`RGRoomX.wall_group` (`+0x68`). The wall prefabs are serialized on layer 13
(`Wall`) with a 1×1 non-trigger `BoxCollider2D` at offset `(0,0.5)`, but
`CreateWall`/`CreateAisleWall` explicitly assign every instantiated wall to
`RGRoomX.EdgeLayer` = 17 (`Edge`). `RGRoomX.cctor` initializes EdgeLayer to 17.

`RGRoomX.CreateWall` omits the five cells `18..22` from both horizontal rows
(`y = room_y_offset - 1` and `y = room_y_offset + room_height`) and both vertical
columns (`x = room_x_offset - 1` and `x = room_x_offset + room_width`). This
creates four five-cell openings. `RGRoomX.CreateAisle` then either builds an open
door/corridor (`entrance=1`) or disables the door and fills the opening with five
wall prefabs (`entrance=0`). `RGRoomX.OnSetRGRandomSeed` computes the runtime
offsets `(41 - width)/2 = 13` and `(41 - height)/2 = 13`; `room_x_offset=0` and
`room_y_offset=0` are only the serialized template defaults.

Serialized `RGRoomX` values from UnityPy `parse_as_dict`:

```text
room_width = 15
room_height = 15
room_type = 1
process = 0
entrance = [0,0,0,0]
floor_list = []
door_open = 1
room_x_offset = 0
room_y_offset = 0
create_with_close_state = 0
```

The serialized entrance array order is `[east, south, west, north]`. The zero
values are the prefab default; `MapManagerLevel.<CreateRoom>d__35.MoveNext`
overwrites entrance bits from `room_relation` for each actual instance.

## 5. Map lifecycle

`MapManager` fields:

```text
RGRandom rg_random; // +0x58
string level;       // +0x60
AudioClip bgm_clip; // +0x68
Color camera_bg;    // +0x70
Vector2Int centerPoint; // +0x80
List<RGRoomX> all_room; // +0x88
bool enterNextMap;      // +0x90
static MapManager _Instance; // 0x0
```

`MapManager.Start` (`0xD26A10`):

1. resolves `RGGameInfo` singleton,
2. loads `RGGameInfo.map_random_seed` (`+0x1C`),
3. calls virtual `SetRGRandomSeed(seed)` through vtable `+0x1E8`,
4. continues map/scene setup.

`MapManagerLevel.SetRGRandomSeed` (`0x103B1D8`) additionally:

- calls base `MapManager.SetRGRandomSeed` (seeds `rg_random`),
- returns unless `RGGameProcess.game_type == Normal (0)`,
- requires `RGGameProcess.this_index >= 1`,
- requires `BattleData.IsNormalMode`,
- requires `BattleData.CompareFactor(10)` (`emBattleFactor.LongMap`),
- requires `RGGameProcess.this_index <= 15`,
- draws `map_random.Range(0,100)`; if `<= 49` (50% chance), increments
  `MapManagerLevel.map_long` (`+0xC0`).

`MapManagerLevel.CreateMap` (`0x1039898`) and `CreateRoom` are not fully decoded.
The room-generation algorithm remains **UNKNOWN**; only the prefab and seed path
are confirmed.

## 6. Scene/object lifecycle

Confirmed Unity mechanisms in use:

- `MonoBehaviour` lifecycle messages (`Awake`, `Start`, `Update`, `FixedUpdate`,
  `OnDestroy`, `OnDisable`).
- `RGRandomInterface` and `RandomBehaviour.SetRGRandomSeed` / `OnSetRGRandomSeed`
  for per-object seed propagation.
- `DontDestroyOnLoad`/scene flow is not yet traced.
- `RGController.Dead` disables colliders and weapons, sets dead flags, and triggers
  the Animator; see `analysis/re/damage.md`.
- `RGBullet.DestroySelf` starts the `Destroying` coroutine; `destroy_time` controls
  the delay.
- `PrefabPool`/`IPrefabPoolObject` are present; `PrefabPool.Take` is used by
  projectile/spawn code. Exact pooling policy is not decoded.

Native runtime must keep explicit lifetime ownership; do not leak Unity-style
implicit destruction semantics.

## 8. Runtime wall generation, doors, and spawn (new evidence)

### 8.1 Runtime wall generation

- `RGRoomX.CreateWall` (`0xDEBE3C`) is the collision source. `LoadRoom` reaches
  it through the virtual room-build path; it is not a direct `bl` from `Start`.
- It reads `MapManagerLevel.wall_list` (`+0x100`; 1×1 wall prefabs with
  non-trigger `BoxCollider2D`), instantiates them, parents to `wall_group`, and
  sets the recovered runtime wall layer. The prefab root is serialized on layer
  13 (`Wall`), but generated instances are assigned to `RGRoomX.EdgeLayer` =
  17 (`Edge`).
- Horizontal rows are at `room_y_offset - 1` and
  `room_y_offset + room_height`, for
  `x = room_x_offset - 1 .. room_x_offset + room_width`. Vertical columns are
  at `x = room_x_offset - 1` and `room_x_offset + room_width`, for
  `y = room_y_offset .. room_y_offset + room_height - 1`.
- Both passes skip `x` or `y = 18..22`, producing four five-cell door gaps.
- Wall prefabs are selected with `RGRandom.Range(0,100)` (<30 selects variant 0,
  otherwise variant 1); both variants have identical collision geometry.
- `RGRoomX.CreateAisle` either opens each gap (door + corridor) or fills it with
  five wall prefabs when `entrance[side] == 0`.
- The 12 serialized colliders (doors/door triggers/bullet colliders) are **not**
  the complete playable collision geometry.

### 8.2 Doors and room state

- `CloseDoor` (`0xDEA4AC`) calls `RGDoor.CloseDoor` on all four door fields
  (`+0x98`, `+0xA0`, `+0xA8`, `+0xB0`) and sets `door_open = false`.
- `OpenDoor` (`0xDEA53C`) calls `RGDoor.OpenDoor` on all four doors and sets
  `door_open = true`.
- `ClearRoom` (`0xDEA5D0`) sets `process = 2`, calls the door-open virtual path,
  plays the room-clear SFX, and sends `SendRoomClearMessage` in multiplayer. It
  does not itself reload the scene.
- `IsClear` (`0xDEBDD8`) returns false if `EnemyMaker.this_count` is nonzero,
  otherwise true if the maker's virtual count is zero.
- `StartRoom` (`0xDEA1A0`) sets `MapManagerLevel.the_room`, `this_room_x/y`,
  `process`, boss info, and game-state delegates; battle-room start invokes the
  door-close path.
- Door open/close Animator clips are decoded: open leaves retract and set the
  collider `isTrigger=true`; closed leaves extend, set the full collider size,
  and keep a one-way inward `PlatformEffector2D`. Closed doors block exiting the
  room but allow entry from the aisle.
- `RGDoor`/`RGDoorTrigger`/`RGAisle` transition timing is recovered as clip
  data (0.5 s door controllers, actual open/close keys 0.133–0.167 s) but native
  collision currently switches final states instantaneously.
- Full door/aisle/traversal state machine and the event-to-manager listener
  remain **PARTIAL/UNKNOWN**; see `analysis/re/room_topology.md`.

### 8.3 Player spawn and `b_point`

- `RGGameSceneManager.CreatePlayer` (`0xDCD3C0`) reads
  `MapManager.centerPoint` (`+0x80`) and builds the initial player position from
  it. Player spawn is therefore **MapManager.centerPoint**, not `b_point`.
- `RGRoomX.LoadRoom` (`0xDEA7CC`) calls `CreateFloor`, then `Transform.Find("b_point")`,
  iterates `b_point`'s children, converts each child to a world position, subtracts
  `room_x_offset`/`room_y_offset`, and appends the result to `RGRoomX.floor_list`
  (`+0x60`). `b_point` is a **valid floor/spawn marker group**, not the player
  root spawn by itself.
- `GetRandomEmptyPos` (`0xDEC9B4`) scans room cells and returns a free position;
  its exact callers for enemy/object spawning remain PARTIAL.
