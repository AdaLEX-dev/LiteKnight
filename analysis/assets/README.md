# Asset Extraction Evidence

`extraction_manifest.json` is generated by:

```bash
tools/asset/extract.sh extract --profile first-pass
```

Manifest v2 records:

- reference APK SHA-256 and bundle root,
- pinned UnityPy version used for the extraction,
- profiles applied,
- source bundle path and SHA-256,
- Unity object path ID (also embedded in the deterministic output filename),
- Unity type,
- object name,
- exported path under `assets/generated/first-pass/`,
- status and notes.

Output filenames always include the object path ID, so rerunning the same
manifest produces the same paths instead of path-ID suffixes that depend on
previously extracted files.

The extracted bytes are **not** committed. `assets/generated/` is gitignored. Only
this manifest and the extraction tooling are committed.

Clean-environment check: deleting `tools/asset/.venv` and
`assets/generated/first-pass/`, then running the extraction command above,
recreates UnityPy 1.25.4 from `requirements.txt` and reproduces 284 entries with
0 warnings.

## Important limitations

- `room/r1_1` itself contains prefab references, not sprite atlases. The shared
  floor/wall sprites live in `res/floor`.
- Several prefab sprite references point to external `cab-*` files; some are
  resolved only when the relevant dependency bundle is loaded. The tool records
  unresolved references as warnings rather than guessing.
- `c01` and `enemy01` are **candidate** identities, not verified character/enemy
  mappings.
- The generic weapon prefab is not confirmed as the Knight's starting weapon.
- Extraction is not yet a full conversion pipeline (no KTX2/OGG/atlas build).

## Controlled Texture2D conversion (2026-10-31)

`tools/asset/extract_unity.py convert-texture` now converts one directly
extractable Unity `Texture2D` to canonical RGBA8 and a deterministic PNG. The
selected reference source is `level-objects`/`f903` (path ID
`-8989119030688471403`, 16x24 RGBA32). Provenance and hashes are recorded in
`analysis/assets/texture_conversion_manifest.json`; generated bytes remain under
gitignored `assets/generated/texture-conversion/`.

Example:

```bash
tools/asset/extract.sh convert-texture \
    --bundle level-objects \
    --path-id -8989119030688471403 \
    --name f903
```

The converter uses UnityPy 1.25.4 and Pillow 13.0.0 (both pinned), rejects
non-RGBA32/RGB24 formats and multi-mip textures, and verifies its PNG round-trip
before writing the manifest.
