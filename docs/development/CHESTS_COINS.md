# Chests and Coins

**Status:** one actual chest prefab and all three actual coin types implemented.

## Recovered evidence

- `chest00` (common bundle): `Animator`, `BoxCollider2D`, `RGChest` with
  serialized `level=0`; child sprites `box03`, `box04`, `box05`, `box06`,
  `shadow`.
- `coin_0`, `coin_1`, `coin_2` (common bundle): `RGCoin` with serialized
  `type=0/1/2`, `value=5/3/1`, `speed=20`, `range=7`.
- `coin_gold`, `coin_silver`, `coin_copper` animation clips provide four
  actual PPtr sprite frames each.
- `RGChest` has `OpenChest`, trigger enter/exit and item trigger methods;
  `RGCoin` has `FindTarget`, `FixedUpdate` and `GetItem`.

## Native minimum implementation

- One `chest00` per dungeon room at `spawn + (0, 2.4)`; closed, interactable
  with `E` within 1.8 units.
- Opening is one-shot. The lid lifts over 0.45 s and is hidden in the open
  state. One `coin_0` (value 5) is spawned. This is a **native test loot**
  extension: the exact RGChest loot table remains UNKNOWN.
- Coins render with the recovered four-frame spin sequence, magnetize toward a
  player within `range=7` at `speed=20`, and are collected within 0.75 units.
  Collection adds the serialized value to the HUD wallet.
- Chests are solid through their recovered collider dimensions. Coin collection
  is removed from the room state; reopening cannot duplicate loot.
- Chest and coin state is preserved across room transitions in memory.
- Wallet value is saved in save v2 (`player.coins`); per-room opened-chest and
  remaining-world-coin state would require save v3 and is documented as a gap.

Reference-derived chest/coin pixels remain local-only and are generated by
`tools/asset/build_item_assets.py`; metadata and evidence are committed under
`analysis/assets/items/`.
