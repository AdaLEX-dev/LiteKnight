# LiteKnight v0.6.0-beta.1

**Release date:** 2026-11-01
**Status:** development beta / pre-release
**Canonical executable:** `build/soul-knight`
**Reference:** Soul Knight 2.6.8, Unity 2018.4.12f1 (local reference only)

This beta is a coordinate- and systems-focused slice of the native LiteKnight
reconstruction. It is not a finished game, not a reference-asset distribution,
and not affiliated with ChillyRoom.

## Highlights

- Strict Living Room coordinate regression: **41/41 checks passed**, covering
  every supplied coordinate, station marker, garden boundary, and autonomous
  walk from five spawn positions.
- Unit suite: **238 cases / 161,569 assertions / 0 failed**.
- Trader stock A/B/A regression: **4/4 checks passed**.
- Gameplay smoke: hub → dungeon → combat → clear → chest → 1-2 → save/load →
  return hub: **passed**.
- The Rogue is now visible in the beanbag. The root cause was a Unity path-ID
  collision: the transparent `nothing` lighting sprite shared a path ID with a
  signboard, so a signboard was drawn over the Rogue. Sprite IDs now carry a
  content hash on collision.
- The Living Room starter chest is a real random weapon chest
  (`hub_weapon_chest`, chest00 visuals) instead of the appointed `chest00`
  duplicate `weapon_021`.
- Materials and unlocked blueprints now survive save/load; the serializer
  previously wrote materials but did not read them.
- Weapon station blueprint/material crafting: no free weapons.
- Trader stock is seeded, persisted, and sold offers are persisted.
- Three vertical world trader pedestals, enlarged mech UI, dedicated materials
  storage UI with icons, restored mission board, portal/grave/NPC visuals, and
  table/object/oxygen collision footprints.

## Run it

```bash
./scripts/prepare-assets.sh
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build build -j"$(nproc)"

./build/soul-knight --start-gui
# or:
./build/soul-knight --hub
./build/soul-knight --hub --review-area rogue
./build/soul-knight --gameplay-smoke --smoke-seconds 25
```

Tests:

```bash
./build/soul-knight-test
python3 tools/qa/living_room_coordinate_regression.py
python3 tools/qa/trader_stock_regression.py
ctest --test-dir build --output-on-failure
```

## Requirements

- Linux/Wayland only (X11/XWayland rejected)
- Vulkan 1.3-capable driver
- SDL3, Vulkan loader/headers, libpng, fmt, CMake, Ninja, C++20 compiler
- Local reference APK/extracted tree to generate the visual assets

## Reference assets / license

The release does **not** include Soul Knight reference assets. `original/`,
`analysis/apktool_out/`, generated reference pixels/audio, and local saves are
excluded. To use the visual mode, provide your own local reference and run
`./scripts/prepare-assets.sh`. Native source is MIT; reference assets remain
proprietary and are not redistributed. See `LEGAL.md` and `docs/legal/`.

## Known gaps

- Full Release/Debug CTest, all 108 PatternRooms, boss/special-room sweep,
  1000-map-seed sweep, and full 302-weapon gallery validation were not fully
  re-run for this beta.
- The autonomous walk regression uses a grid collision model, not the real
  player controller.
- No dedicated Rogue sitting animation clip; the recovered body is positioned in
  the beanbag.
- Exact blueprint acquisition loop is not recovered; the station gate/cost/
  craft/persistence are implemented.
- Full EnemyAI04/pathfinding, exact procedural dungeon algorithm, reference save
  format, plant/mech economy tables, and full crit/element/status behavior remain
  partial.
- Visual acceptance is still required for pose, pedestal scale, icon
  readability, and UI cropping at non-16:9 aspects.
- `build-release/soul-knight` is an older synthetic-scene binary; use
  `build/soul-knight`. `/build/soul knight` is not present in this tree.
